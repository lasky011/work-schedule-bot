## 2. Календарь ресторана (не календарь Python)

`date.weekday() >= 5` **нельзя** использовать как «выходные».

После `f188df1` / `f24e76a`:

| | Дни | Код |
|---|---|---|
| Будни ресторана | Пн–Чт и **воскресенье** | `weekday` |
| Выходные ресторана | **только Пт и Сб** | `weekend` |

Стандартные часы (`constants.SHIFT_HOURS`):

- утро будни: **12.5** ч
- утро Пт/Сб: **14.5** ч
- вечер будни: **10.0** ч
- вечер Пт/Сб: **12.0** ч

Напоминание внести часы (`SHIFT_END_NOTIFY`):

- утро Пн–Чт, Вс → **23:05** того же дня
- утро Пт, Сб → **01:05 следующего** дня
- вечер Пн–Чт, Вс → **02:05 следующего** дня
- вечер Пт, Сб → **04:05 следующего** дня

В `hours_notification_loop`: если сейчас час **< 12**, смена для ночного напоминания — **вчерашняя** дата. Не ломать.

Часовой пояс: **Europe/Moscow**.

## 3. Что считается сменой

- Утро / вечер: **первый час в ячейке < 14 → утро, иначе вечер**.
- Рабочая смена: ячейка с часом (`11:00`, `16-23`, `13:00-15:00`, голое `11`) **или** слово **`Оф`** (менеджер за официанта).
- **Не смена:** пусто, `nan`/`none`, `выходной`, `-`, `—`, заметки вида **`До 04:00`**.
- Стажёрские интервалы (`13:00-15:00` и т.п.) — тоже смены; тип всё равно по первому часу.
- Хвосты в имени вроде `с 16:00` / латинская `C 16:00` срезать при поиске человека, не считать частью имени.

Красные дни в подписях дат: Пт, Сб **и** `RU_HOLIDAYS` в `bot.py` (1–8 янв, 23 фев, 8 мар, 1 и 9 мая, 12 июн, 4 ноя).

## 4. Периоды графика и таблица

- Период всегда **1–15** или **16–конец месяца**. Не «календарная неделя зарплаты».
- Живые GID — таблица `sheet_periods` в Postgres. `constants.SHEET_GID_MAP` — только запасной хвост, его **не** считать актуальным августом.
- Нет GID на день = график **не опубликован**, не «все выходные».
- Алерт админу про следующий период — только за **2 дня** до его начала (`WARN_DAYS_BEFORE_NEXT_PERIOD`). Текущий период без GID — сразу.
- Колонка дня: `get_day_column` **один раз**. Не перечитывать числа правее как дни — там блок статистики (`SCHEDULE_MAX_DAY_COL = 16`, коммит `dd47c8d`).
- На одном листе несколько блоков с **повторной** строкой дат (кальян ниже официантов). Парсер людей это учитывает; не упрощать до «одна шапка дат».
- Неделя в UI: **пн–вс**.

## 5. Имена, роли, поиск строки

- `find_row(..., target_role=)` обязателен, если у человека роль известна. Одинаковые имена в разных отделах (Дарья бармен / Дарья хостес) — **не смешивать**.
- Fallback `target_role=None` только если `person_has_ambiguous_role(name)` ложно. Иначе можно взять чужую строку.
- Fallback точного имени по первой колонке нужен для листов 16–30, где шапка роли может не совпасть с кнопкой.
- Нормализация ролей не трогать без нужды: `Менеджер`↔`Менеджеры`, `Кальянщик`↔`Кальян`, `Официанты`→`Официант`, `Стажеры`→`Стажер`. Ставка кальянщика ищется по **`Кальян`**, не только по `Кальянщик` (`a5406ae`).
- Статус «на смене / выходной» для карточки дня считается **по каждой роли отдельно**. Дарья может работать барменом и быть выходной как хостес — во «замену» она идёт только по хостес (`5fe2260`).
- Если `get_people_for_day` пропустил работающего, а `find_row` его видит — человека **добавить в «работают»**, не терять.
- Менеджеров не выкидывать из коллег/сравнения (когда-то ломали, чинили `9c47d46`).
- Сравнение: себя не добавляют руками; максимум **3** коллеги; периоды сравнения показывать **все**, не только текущий.
